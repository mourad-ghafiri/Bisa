Download Bisa

Available for macOS 11 or later — one application for Apple Silicon and Intel Macs, signed with a Developer ID and notarized by Apple, so macOS opens it without a word. Linux and Windows are coming soon. Free and open source.

What you need

  • A Mac on macOS 11 or later.
  • At least one coding harness, installed and signed in — Claude Code, Codex CLI, OpenCode, GitHub Copilot CLI, Grok Build, Gemini CLI or any ACP agent (which does what).
  • git on your PATH, for projects.

Verify the download

Each release on the Releases page is two files: the disk image and its SHA-256. The checksum proves the bytes are the ones published; the image is signed with a Developer ID and carries Apple's notarization ticket inside. The getting-started guide shows how to check both.

Open the image and drag Bisa to Applications.

First launch

The app carries its own node: nothing else needs to be running. The first launch makes ~/.bisa and your identity, then checks five things, each with a fix:

  1. git is on your PATH.
  2. At least one harness is installed.
  3. The General Agent runs on an installed harness, with a model.
  4. The Workflow Agent does too.
  5. The Decision-Making Agent is switched on and able to answer — one click chooses who judges.

It installs nothing for you: where something is missing, it shows the official line to copy.

Your first goal

Press New goal and say what you want in one sentence. Choose how it runs — auto (the default) designs, adopts and runs it; guided brings you the proposal to adopt; manual opens the designer. What needs you lands in the Inbox.

Or talk first: the General Agent and the Workflow Agent are in the general channel from the start.

The command line

The app's node is also a command line, inside the application: what the window does, it can do too, and while the app is open it talks to the same node. The getting-started guide says how to reach it, and the command line reference lists everything it does.

Build from source

You need Rust (stable), Node.js 20 or later with npm, and the Tauri CLI. Take the source from the repository: on a Mac, one script builds the application the first time and opens it every time after — the setup guide walks through it.

It builds both halves for Apple Silicon and Intel in one bundle and signs it ad hoc: it opens on this Mac and on no other. A copy to give to someone is the signed release above.

Linux and Windows — coming soon

Signed releases for Linux and Windows are coming soon. Today, the source builds the same two halves — the node and the desktop shell — into an AppImage and a .deb, or an installer, unsigned, as the setup guide says. The menu bar icon, system notifications and the network read-out are macOS-only.

Updating

Download the next release and replace the app. You › Update in the app asks GitHub for the latest release when you open it and takes you to the download and to what changed; the app does not update itself, and a new release may not read a workspace an older one wrote — there is no migration. Before the first launch of the new one, rename your workspace folder, ~/.bisa, so the old one is kept aside.

The changelog says what changed in each release.

Removing it

Move Bisa from Applications to the Trash. What it kept is yours, in three folders: ~/.bisa (your workspace), and the window's state and fallback log under ~/Library/Application Support/dev.bisa.bisa and ~/Library/Logs/dev.bisa.bisa.
