# Getting help

| You want to | Go to |
|---|---|
| ask how to do something, or why something behaves as it does | GitHub Discussions — *Q&A* |
| share an idea or a wish | GitHub Discussions — *Ideas* |
| report something that does not work | an issue — [the forms](.github/ISSUE_TEMPLATE) |
| report a vulnerability | privately — [SECURITY.md](SECURITY.md) |
| learn to use Bisa | [Getting started](docs/guide/getting-started.md) and [the guides](docs/README.md) |
| contribute | [CONTRIBUTING.md](CONTRIBUTING.md) |

Before you ask, search Discussions and the issues — open and closed — and read the guide of the
feature you are using. When you ask, say which release you run (`bisa --version`, or About in the app),
on which machine, what you did, what you expected and what happened. Attach the diagnostic log
(`bisa logs`) only after reading it: remove anything that is yours alone.

**Supported versions:** the latest 0.x release. Inside 0.x an upgrade is in place and keeps your
workspace ([Compatibility](docs/reference/compatibility.md)), so the first answer to many problems is
to upgrade.

Bisa is maintained by volunteers; answers come as time allows. Issues are read within a week
([Triage](docs/contributing/triage.md)).
