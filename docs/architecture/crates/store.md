# bisa-store

**The filesystem is truth. `index.sqlite` is a cache.** Every durable fact is a file — a signed
event in a journal, a snapshot, a truth record — and the index exists to find things. It is stamped
with `SCHEMA_VERSION`; a mismatch — or a file that fails `PRAGMA quick_check` — discards it and rebuilds it from the files, and every open reconciles the live runs — every open goal's and every run of the workspace's — with their snapshots (`reconcile_live`).
The store writes records and reads
them back; it never creates a working directory, never runs `git`, never launches a process — those
are the engine's ([engine](engine.md)). `Workspace` in `workspace.rs` is the facade every other crate
holds.

### On disk

The tree is [`docs/reference/workspace-layout.md`](../../reference/workspace-layout.md); `paths.rs`
is its only source. Three tiers:

- **Truth, synced** — `goals/<id>/journal.jsonl`, `goals/<id>/state/` (the goal, its runs, its
  work items), `workflows/` (the library's `state/`, and each run of the workspace's journal and `state/`
  under `runs/<RunId>/`), `projects/<slug>/project.json`, `channels/`, `agents/`, `teams/`,
  `skills/`, `connectors/`, `conversation/`. A goal's `listening` is a field of its snapshot.
- **Truth, this machine's** — `projects/<slug>/workstreams/<id>.json`, `mcp/`, notes, review notes,
  `machine.json`, `run/`, `ide/`, `identity/` (keys, `codehost/<kind>/` tokens, `connectors/<connector>/` account records, `git/profiles/`, hook secrets),
  `workflows/listening/` (which library workflows are On, and what each listens with) and `events/`
  (the signal queue `queue.jsonl`, each listener's memory under `listeners/`, a check start's
  folder under `scratch/`).
- **Cache** — `index.sqlite` and its `-wal`/`-shm` siblings.

A workstream's checkout is **derived, never stored**: `checkout_in(&project, &workstream)` is the
one place a record becomes a directory — the project's resolved root for the primary,
`projects/<slug>/workstreams/<id>/` for a worktree or a copy. `workstream_checkout(&workstream)`
is the same derivation for a caller without the project in hand.

## Entry points

- `Workspace::open(root)` / `open_with_keystore(root, Box<dyn KeyStore>)` — bootstrap in one order
  and nowhere else: the owner member, the index rebuild if it was discarded, the two core agents that hold a record,
  the `general` channel. An unreadable `governance.json` stops the open with `StoreError::Unreadable`,
  which names the file and `scripts/reset-dev-workspace`; an unreadable goal, run, work item or
  workflow snapshot met by the rebuild or by `reconcile_live` is skipped through `tolerated` with an
  error line naming it (`list_work_items_readable` answers the skipped ids beside the items), so a
  crash between two builds never leaves a workspace nobody can open.
- The `Workspace` methods, in two kinds: **readers** (`get_*`, `list_*`, `read_*`, `validate_*`,
  `journal`, `usage`, `search`, `signer_for`, …) that any layer may call, and **writers**
  (`create_*`, `put_*`, `update_*`, `save_*`, `delete_*`/`remove_*`, `transition_*`, `record_*`,
  `append_*`, `attach`/`detach`, `mark_*`, `set_*`, `install*`, `post_*`, `react`, `retract`,
  `ensure_*`, …) that only the engine calls — `crates/bisa-node/tests/it/layering.rs` derives that
  list from `impl Workspace` by verb, so a new writer is denied in the node the moment it exists.
- `subscribe_store_events()` — the broadcast the engine's conversation listener and the node's SSE
  ride on.

## What this crate refuses to do

- create a directory for work, run `git`, or launch a process — a record is cheap and reversible,
  a filesystem effect is neither;
- migrate: an older on-disk shape is refused by name, never converted;
- resolve a setting, validate a workflow's rules or advance a run by itself — the core does; the
  store verifies, writes and indexes;
- know about HTTP, a harness, or a relay.
