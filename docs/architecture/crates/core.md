# bisa-core

The zero-I/O foundation. Every domain type, every rule, the workflow definition and its validation,
the run machine, the GEP kind registry, the settings registry and the capability vocabulary live
here as pure functions with unit tests. Nothing in this crate opens a file, a socket or a database:
the manifest forbids `tokio`, `rusqlite`, `axum`, `reqwest` and `hyper`, and a test holds the ban.
That is what makes rule 3 of the architecture true — *every domain invariant is enforced in exactly
one place* — rather than aspirational: a rule that needs no workspace on disk is a rule that can be
unit-tested and reused by the store, the engine, the node, the CLI and a peer's ingest alike.

## Entry points

- **`WorkflowRun::apply(&mut self, RunEvent, now) -> Result<Vec<RunEffect>, RunError>`** — the
  one function that changes a run: it validates the event against the step's kind and state,
  records it, settles the graph to a fixpoint, and returns the effects the engine interprets.
`WorkflowRun::accepts(kind,
  event)` is the table it agrees with; `status()` is the projection a goal reads.
- **`Workflow::validate(&self, &ValidationCtx) -> Vec<Problem>`** — pure, exhaustive; the store
  calls it on every create, update, amendment and start, and the Workflow Agent's `validate_workflow`
  calls it without writing. Cron and schema syntax reach it through the `SyntaxChecks` seam the
  store implements, so the core depends on neither crate.
- **`Workflow::bind_inputs(given) -> Result<inputs, InputError>`** — the one input contract:
  defaults filled, a wrong kind, a missing required input and an undeclared name refused. A run
  starts through it and an amendment is re-bound through it.
- **`template::placeholders` / `render`** — parse a step string's placeholders; render them against
  a `TemplateCtx`. An unknown root is a parse error, an absent value is `Unresolved` with its
  `Absence` — which step, and whether it has not run, is still running, failed, yielded nothing or
  yielded other fields — and nothing is ever left verbatim.
- **`Goal::status(&self, Option<&WorkflowRun>) -> GoalStatus`** — the projection; a goal stores no
  status.
- **`WorkItemState::apply`** and **`Workstream::apply`** — the same shape for the two smaller
  machines. `Workstream::apply` is kind-aware: the primary refuses `Close`, `PrOpened` and `Merged`
  with `WorkstreamError::Primary`.
- **`settings::resolve` / `resolve_all` / `check_write`** — the only resolution of a settings key.
- **`kind::*`** — the sets a sync walk, an ingest and an encryption decision switch on.
- **`Tags::new`, `Slug::new`, `StepId::new`, `RelPath::parse`, `AgentId::new`** — parse, don't
  validate: a value of these types is legal by construction.
- **`Workstream::require_repository` / `require_own_branch`** — the two refusals the CLI, the node
  and the engine all express (a copy has no repository; only a worktree has a branch of its own).

## Errors

`CoreError` in `error.rs` is the sum of every module's own error type (transparent `#[from]` arms —
`RunError`, `TemplateError`, `WorkItemError`, `WorkstreamError`, `ChannelError`, `AgentError`,
`TeamError`, `SettingsError`, …) plus the parse refusals listed above. Upstream, every one of them is
a refusal: the store wraps them as `StoreError::Core` or the matching transparent arm,
`StoreError::is_refusal` answers true, and the node renders them as **400** — or **409** for a
`RunError` (the run is finished, the step is not live, the kind does not accept the event), a state
machine's `Illegal` move, and the permanent objects ([node](node.md)).

## Tests

Unit tests sit beside each rule in `#[cfg(test)] mod tests`; the run machine carries property tests
over its kind table and its totality. `tests/it/layering.rs` holds the workspace-wide build rules: the
crate graph equals `allowed_edges()`, core does no I/O and never panics, no test source contains a
destructive command, consent is minted in one place, the consented git tier has two named engine callers,
and no agent-facing crate names it. `tests/it/docs.rs` holds the documentation set to the code (links,
paths, crate pages, the decision index, settings keys, the retired planning voice). `tests/it/shapes.rs`
holds every type read from JSON to `deny_unknown_fields` — or to a named excuse — and reads a table of
stored shapes whole and refuses each with one key too many.

## What this crate refuses to do

- perform I/O of any kind, or depend on a runtime;
- know a path on disk, a harness, a process, a socket or a clock;
- accept a database constraint or a route check as the definition of a rule;
- panic on anything a user or a peer controls.

`Step::summary` is the one line a person judges a step by on the proposal card — the first sentence of an agent step's instructions and its assignee, a human step's prompt and options, what a start begins on, a check's command, a decision's branches, what a wait waits for, the signal an emit raises, where a notification goes, a child goal's statement, how a run ends — with `first_sentence` and `ValueRef::word` beside it; unit-tested.
