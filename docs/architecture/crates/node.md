# bisa-node

The axum control plane: a unix socket (mode 0600) and an optional loopback TCP listener, both
behind one bearer token; the routes, their documented table, the SSE stream, and the mapping from a
typed refusal to a status code. **The node reads the store; every write goes through the engine**
([07 — Layering](../07-layering.md), rule 2), and a test derives the list of store writers from the
store's own source so a route that reaches for one fails the build. A route parses, delegates and
renders; it holds no rule of its own.

### Authentication

Every route on both listeners wants `Authorization: Bearer <token>`, or `?token=` where a header
cannot be sent. Six exceptions, each with its own reason (`auth::is_exempt`): `GET /health` (a liveness probe carries
no authority), `POST /hooks/{host}/{step}` (the listener's own secret), `GET /connectors/oauth/callback` (the browser
arrives with a one-shot `state` the engine minted minutes ago, on a listener bound only while a
connection is pending), the A2A card and endpoint, `GET /addons/{id}/files/{*path}` (an installed
bundle's files, for a sandboxed frame that holds no token), and a terminal session's four doors —
`POST /sessions/{id}/report`, `/guard`, `/exit` and `/close` — which take the session's own secret
in the token's place.

### The SSE contract

`GET /events` streams `{stream, payload}` frames:
`engine` carries an `EngineEvent`; `conversation` carries `{scope, kind, event_id, author, snippet,
unread_count, latest}` — `latest` what now stands as the room's last words, by the rule the lists
answer by (`Workspace::latest_message`: a post takes the place, a retraction gives it back, a
reaction or a membership event leaves it), so a list that follows the bus mirrors nothing;
A row that moved and has no frame is said in the log: `inbox::delta` keeps the read that failed
(`try_delta`) and warns with the row's `key`, since a frame that is not sent leaves a row stale with
nothing on screen to say why; an activity row the Inbox cannot read is warned once with its `seq`,
as the Pulse says its own. `inbox` carries `{key, kind, unread_count, needs_action_count, latest_at, read, handled}` — and
`notice_count`, `unread_notices` when the cause could have moved them (an engine fact, a read
marker; a message leaves them out and the client keeps what it holds) — and rides alongside the
frame that caused it, so a row mutates in place; the row it names is `notices::target_of`'s: the
goal a gate, a question, a decision or a run's state concerns, the workstream or project a notice
concerns, the workflow or the goal a listener that failed belongs to.

## What this crate refuses to do

- write to the store — a route calls the engine;
- hold a PTY: a shell is a capability of one machine, not a fact about the workspace, and the
  terminal is a desktop-shell command ([ide/01](../ide/01-trust-boundary.md));
- trust the middleware for consent — `consent::from_request` re-reads the token;
- let the reference and the router disagree — the route tables are the reference's source.

`NeedsAction` carries `proposal: ProposalView` for an adoption (`adopt:<workflow>@<revision>`) and for a held amendment (`amend:<run>@<workflow>`, the held copy) — the design's description, every step with `Step::summary`, assignee, join/on-fail/visits notes, its edges and inputs — built by `inbox::with_proposals` over `proposed_workflow(subject)` for live and durable actions alike; `inbox::durable_actions` rebuilds the newest undecided `amend:<run>@` question while the run is unfinished, the `adopt:` question when nothing runs, and the design question (`ask_human:<goal>`), all through `pending_question`, tested in-crate.
