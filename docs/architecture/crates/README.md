# The crates — one page per layer

One page per crate, and one for the desktop. A page is the map of a layer: what it owns, where each
thing lives, the invariants it holds and the test that holds each, how it fails, and where a change
goes. The source is the territory; a page names every module of its crate, and a test
(`crates/bisa-core/tests/it/docs.rs`) fails when a module is added without a sentence here.

Read [07 — Layering](../07-layering.md) first for the rules between the layers; read
[10 — Runtime flows](../10-runtime-flows.md) for how a request crosses them.

## The skeleton every page follows

| Section | Answers |
|---|---|
| **Purpose** | what this layer is for, in one paragraph, and the one rule it exists to keep |
| **Where things live** | every `src/*.rs` module, what it owns, the public types worth knowing |
| **Entry points** | the functions and types the layer above calls |
| **Invariants held here** | each rule with the test that holds it |
| **Errors** | the error type, its variants, and what each becomes at the next boundary |
| **Extension points** | where a new X goes, with the files in order and the gate that catches a miss |
| **Tests** | where the tests are and what fixtures they use |
| **What this crate refuses to do** | the things it must never be made to do |

| `bisa-http` | [http](http.md) | the one HTTP client set: a proxy policy over swappable `reqwest` clients, and the environment a child is handed to obey it; the one reader of a server-sent event stream | — |
| `bisa-netrules` | [netrules](netrules.md) | the one grammar of a host pattern (`host[:port]`, `*.suffix`), the loopback names and the headers a connector definition may never set — pure, shared by the domain, the connectors client and the security rules | — |

| `bisa-log` | [log](log.md) | the diagnostic log: one subscriber per process, a JSON-lines file under the workspace's `logs/`, the words the `logging.*` settings speak — shared with the desktop shell by path | — |
