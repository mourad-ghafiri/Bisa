# bisa-vcs

`git` as typed, time-boxed, argv-only subprocess calls, in two tiers. Synchronous, no tokio, no
workspace dependency; every function takes the repository path explicitly — there is no "current
repository". The safe tier reads, stages and commits and **cannot revert a file**; the consented
tier moves the tree and **writes a recovery ref first**, so nothing in this crate can make a change
unrecoverable.

## Where things live

| Module | Owns |
|---|---|
| `lib.rs` | the module list, the re-exported types, the discipline in prose (two-phase availability, typed errors, argv only) |
| `exec.rs` | the one process launcher: time-boxed, `LC_ALL=C`, never prompts (`Timeouts`, `Output`); each pipe drained on its own thread and a read that fails is the call's failure, never a truncated answer read as whole; a stdin write is judged after git's own exit — a child that stopped reading is git's refusal in git's words, and a short write is an error only when git succeeded |

A pathspec reaches git as `:(top,literal)<path>` after `literal_pathspec` refuses a leading `-` or
`:`, an absolute path and a `..` component; `blame` alone receives the bare validated path, because
`git blame` reads pathspec magic as a file name.

## Entry points

The free functions in `git.rs` and `interactive::ops::*` (a shared `Git` with default timeouts);
`Git::new(timeouts)` for a caller that wants its own, `Git::without_env` (a name removed from every child, the hardened names refused — the proxy the node inherited that the person said not to use) and `Git::with_config` (`-c key=value` on every invocation, after `--no-pager` — `http.version` when the platform speaks HTTP/1.1 only), and `Git::with_env` — a test seam
(`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`) that hides a developer's own config from one handle
without touching the process environment; the hardened names are refused.

## Errors

`VcsError`: `NotARepository(path)`, `NoRemote`, `NotAuthenticated`, `IdentityUnset`, `Dirty { path,
details }`, `Conflict { message, paths, in_progress }`, `NotFastForward { ahead, behind }`,
`InProgress(op)`, `NothingToStash`, `StashMoved { index, commit, now }`, `InvalidArg { what, value }`,
`Command { what, code, stderr }`, and the transport failures. `classify` turns git's words into one
of these exactly once (a conflict's paths and operation are read from the repository by the
consented verb that met it); the node renders `Dirty` as **409** with git's sentence, `Conflict`,
`NotFastForward`, `InProgress`, `NothingToStash` and `StashMoved` as **409** with a `code` and their
facts in `detail`, the rest as **400**.

## Tests

`tests/it/git.rs`, `tests/it/interactive.rs`, `tests/it/snapshot.rs` (a checkout's snapshot staged
through a private index, so neither the person's index nor the tree moves) — each on a `tempfile` repository with a local bare
`origin`; nothing is deleted by hand, a worktree that must vanish is moved aside. The profile and
account tests run under `git_with_global`, a handle whose global file is a temp file
(`Git::with_env`), so no test reads or writes a developer's own configuration.

## What this crate refuses to do

- depend on anything of ours;
- revert a file from the safe tier;
- run a tree-moving operation without a recovery ref;
- prompt, read a cwd, or spell a plain force;
- write an include into a repository's local config, or a global include for a file it was not
  handed — the engine decides which files are profiles.
