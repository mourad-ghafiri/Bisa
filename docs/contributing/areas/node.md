# The node

For a person, the node is the daemon that runs a workspace — `bisa node`, the desktop's sidecar — that
the desktop and the command line talk to. In code it is `crates/bisa-node`, the axum control plane: a
unix socket (mode 0600) and an optional loopback TCP listener behind one bearer token, the routes and
their documented tables, the server-sent event stream, and the mapping from a typed refusal to a status
code. A route parses, delegates and renders; it holds no rule of its own.

## Where it lives

- `crates/bisa-node/src/lib.rs` — binding the socket, `Query<T>` and `Body<T>` (the one reader of a query and of a body), the router, the SSE envelope, the panic layer.
- `crates/bisa-node/src/auth.rs` — the bearer token and its named exceptions.
- `crates/bisa-node/src/dto.rs` — every request and response type, each deriving `JsonSchema`; `ErrorCode`.
- `crates/bisa-node/src/route_docs.rs` — `RouteDoc`, and the sections every module's `ROUTES` table feeds.
- `crates/bisa-node/src/i18n.rs` — the request's language, and the sentence an error is said in.
- One module per family — `crates/bisa-node/src/goals.rs`, `crates/bisa-node/src/workflows.rs`, `crates/bisa-node/src/projects.rs`, `crates/bisa-node/src/conversation.rs` and the rest — and the IDE's under `crates/bisa-node/src/ide/`.
- `crates/bisa-node/src/bin/api-schema.rs`, `crates/bisa-node/src/bin/api-docs.rs` — the schema bundle the desktop's types are generated from, and the HTTP reference.
- `desktop/src/api.ts`, `desktop/src/bus.ts` — the desktop's client and its event bus; `desktop/src/types.gen.ts` is generated, never edited.
- `docs/reference/http-api.md` — generated by `just gen-api-docs`, never edited by hand.

## Rules a change must keep

- The node reads the store; every write goes through the engine — a mutation is an engine function, and `crates/bisa-node/tests/it/layering.rs` derives the store's writers by verb and denies them here ([07 § Rule 2](../../architecture/07-layering.md#rule-2--the-node-reads-the-store-every-write-goes-through-the-engine)).
- Every route but the named exceptions answers 401 without the token; the token is written before any door is bound; no harness child inherits it ([crates/node § Authentication](../../architecture/crates/node.md#authentication)).
- `HumanConsent` is minted in one place, `crates/bisa-node/src/ide/consent.rs`, from the `Authorization` header alone — a token in the query proves no click (I38).
- Every body is read through `Body<T>`, and every type it reads refuses a key nobody knows; a body that does not fit is the documented 400 in the error body's shape.
- A refusal is typed and mapped — 404 missing, 409 a state machine or a conflict, 400 a refusal, 500 a malfunction said in one sentence with the fault in the log; a refusal a client tells apart carries a `code` ([crates/node § Errors, mapped](../../architecture/crates/node.md#errors-mapped)). Its words are a catalog message, never a literal.
- Every documented route is mounted, every route module has a `ROUTES` table, every URL the desktop builds is documented, and every body is in the schema the desktop's types come from.
- A frame keeps [the SSE contract](../../architecture/crates/node.md#the-sse-contract): a row mutates in place.
- The generated files travel with the change: the schema, the TypeScript types, the HTTP reference ([Release](../release.md#generated-files-travel-with-the-change)).

## Testing a change

- `scripts/test module node routes` — mounted, documented, called by the desktop; 401 without the token.
- `scripts/test module node layering` — the write rule, the one reader, the one extractor, the schema.
- `scripts/test module node bodies`, `scripts/test module node auth` — limits and content types; the bearer's exceptions as one table.
- `scripts/test module node <module>` for the family you touched; `FEATURES=a2a scripts/test module node a2a` for the A2A routes.
- `desktop/src/scenarios/bodiesFitTheSchema.test.mjs`, `desktop/src/apiModel.test.mjs`, `desktop/src/busModel.test.mjs` — what the desktop sends and reads, held to the schema.
- `just check-api-docs`, `just check-types` — the generated reference and types are not stale.
- The journey `crates/bisa-cli/tests/it/e2e/the_nodes_wire.rs` — who may call, a body it cannot take, a stream told the node is stopping.
- One module at a time; the whole workspace (`just verify`) only at the end of a pass ([Running](../testing-rules.md#running)).

## Compatibility

- [The HTTP API and its events](../../reference/compatibility.md#the-http-api-and-its-events) is public: every route and its method, the fields a request accepts and a response carries with their types, every `ErrorCode`, the streams of `GET /events` and their frames.
- Inside 0.x a minor or patch release never breaks the public contract: add routes, optional request fields, response fields, codes, events and topics — a client ignores what it does not know and switches on `code`, never on the words.
- A new required field, a renamed route or field, or a new status for an existing case cannot be made by addition; it waits for 1.0.0, which brings a migration tool ([the first major release](../../reference/compatibility.md#the-first-major-release)).
- Declare the compatibility of your change in the pull request.

## Review focus

- Does the handler only parse, delegate and render, with every mutation in the engine ([code review](../review/code.md))?
- Does the route need the token, and does nothing secret reach an answer, a query string or the log ([security review](../review/security.md))?
- Is the body bounded and the list paged and clamped ([performance review](../review/performance.md))?
- Is the change to a route, a field or a code additive, and does the regenerated reference show it ([compatibility review](../review/compatibility.md))?
