# Settings

Settings are a person's preferences and a workspace's decisions — appearance, the editor, git,
agents, security, events, budgets and the rest — changed in the desktop's Settings screen, in a
project's About › Settings, or with `bisa settings`. In code they are one registry in `bisa-core`
(`REGISTRY`: a `def!` per key with its kind, default and the scopes that may hold it), three files on
disk resolved Project → Workspace → Machine → default, one write door in the engine, and a reference
page generated from the registry.

## Where it lives

- `crates/bisa-core/src/settings.rs` — `REGISTRY`, the kinds, the defaults, `ScopeSet` and resolution; typed readers beside it (`crates/bisa-core/src/git_settings.rs`, `crates/bisa-core/src/event_settings.rs`, `crates/bisa-core/src/network_settings.rs` and others).
- `crates/bisa-store/src/settings.rs` — the three files: `machine.json`, `settings.json`, a project's `settings.json`.
- `crates/bisa-engine/src/settings.rs` — the one write door (`set`, `unset`) and `refresh`, which tells every module that reads a key live.
- `crates/bisa-node/src/settings.rs` · `crates/bisa-cli/src/settings.rs` — `GET/PUT /settings/{scope}`, `GET /settings/resolved`, and `bisa settings`.
- `locales/en/settings.ftl` — each key's label, help and choice words (`setting-<key>`).
- `desktop/src/views/Settings.tsx` · `desktop/src/views/_settings/` — the screen and its panels: `RegistryPanel.tsx` over a group of keys, the origin badge (`settingOriginModel.mjs`), the rail (`settingsLink.mjs`), the three read phases (`loadModel.mjs`).
- `desktop/src/shell/settingsStore.ts` — the registry read once a session, the resolved values read again on every `settings_changed`.
- `docs/reference/settings-keys.md` — generated by `just gen-settings-docs`; never edited by hand.

## Rules a change must keep

- A key is declared once, in `REGISTRY`, with the scopes that may hold it; the registry carries no words — the label, the help and every choice's word are messages in `locales/en/settings.ftl` ([Add a setting](../recipes.md#2-add-a-setting)).
- A value written to a scope the key does not allow is refused at write time, naming the allowed scopes — never stored and ignored ([ide/13 § Resolution](../../architecture/ide/13-settings.md#resolution)).
- A setting is written through one door, the engine's `settings.rs`: everything that holds the key reads it again, and the bus says which keys moved ([ide/13 § Resolution](../../architecture/ide/13-settings.md#resolution)).
- A key nobody reads is a lying panel: every key has its reader — an engine read, or the panel that renders it ([Add a setting](../recipes.md#2-add-a-setting)).
- Furniture is not a preference: dock positions, pane sizes and where a person was stay in `localStorage`, with no registry key ([ide/13 § Three scopes](../../architecture/ide/13-settings.md#three-scopes)).
- A panel never draws a default before its read lands, and a re-read keeps the last answer and says so ([ide/13 § Every panel reads the same way](../../architecture/ide/13-settings.md#every-panel-reads-the-same-way)).
- A sentence that sends a person to a panel spells the path as the rail shows it — *Settings › group › panel* (`desktop/src/scenarios/settingsPaths.test.mjs`).
- The reference page is generated, and a key quoted in any page must be registered ([ide/13 § Every key](../../architecture/ide/13-settings.md#every-key)).

## Testing a change

- `scripts/test lib core settings` — the registry's unit tests, `resolve_all_covers_the_registry` among them.
- `scripts/test module engine settings` · `scripts/test module node settings` · `scripts/test module store settings` — the write door and who hears it, the routes and their refusals, the files on disk.
- `scripts/test crate i18n` — a key without its message, a choice without its word, a word for a value the key does not take.
- `scripts/test desktop views/_settings`, then from `desktop/`: `node --test --import ./src/i18n/preload.mjs src/scenarios/settings.test.mjs src/scenarios/settingsPaths.test.mjs`.
- The journey `crates/bisa-cli/tests/it/e2e/settings_security_and_the_log.rs` — a key at each scope, nearest wins, a scope refused by name, unset falling back, every write heard on the bus — under `scripts/test module cli e2e`.
- Guards: `just check-settings-docs` (the reference is current) and `crates/bisa-core/tests/it/docs.rs` (a key quoted in prose is registered).
- One module at a time; `cargo test --workspace`, `npm test` and `just verify` close the pass ([Testing rules § Running](../testing-rules.md#running)).

## Compatibility

- Every key, its kind, the scopes it may be set at and its choices are public contract ([Settings keys](../../reference/compatibility.md#settings-keys)); the three files are part of [the workspace on disk](../../reference/compatibility.md#the-workspace-on-disk); the `/settings` routes and `bisa settings` are [the HTTP API](../../reference/compatibility.md#the-http-api-and-its-events) and [the command line](../../reference/compatibility.md#the-command-line).
- A change stays additive: a new key, or a new choice beside the old ones. A default changes only in a minor release, named under *Changed* in `CHANGELOG.md` — never in a patch.
- Renaming or removing a key, narrowing its scopes or removing a choice cannot be made by addition: the key is deprecated and still read for the rest of 0.x, and the removal waits for 1.0.0, which brings a migration tool ([Deprecation](../../reference/compatibility.md#deprecation), [Keeping compatibility](../compatibility.md)).
- Declare your change's compatibility in the pull request.

## Review focus

- The scope: a fact about this machine at `Machine`, a decision shared with collaborators at `Workspace`, a property of the code at `Project` ([ide/13 § Three scopes](../../architecture/ide/13-settings.md#three-scopes)).
- The reader exists and hears a change; nothing writes a setting past the engine's door ([Code review](../review/code.md)).
- A key that switches a guard, a grant or a reach: what its default lets happen, and at which scope a person may loosen it ([Security review](../review/security.md)).
- The label, the help and the generated page say what the code does ([Docs and language](../review/docs-and-language.md)); the key only grows ([Compatibility review](../review/compatibility.md)).
