# The desktop

The desktop is Bisa's window: every screen, the conversation surface, the overlays, the footer's
read-outs, the menu bar icon and the notifications that reach a person outside the window. In code it
is a Tauri 2 shell around a React 19 app that spawns the `bisa` node as a sidecar and talks to it over
the HTTP API. The shell (`desktop/src-tauri/`) holds what has a machine's blast radius — the PTYs, the
file dialogs, the login environment, the menu bar icon, the window's place; the app (`desktop/src/`)
holds the screens, and every fact a screen computes lives in a pure `.mjs` model with its types and
its test.

## Where it lives

- `desktop/src/views/` — the routed screens and their pieces: `_studio/`, `_goal/`, `_workflow/`, `_workbench/`, `_settings/` and the rest.
- `desktop/src/shell/` — the chrome that outlives every screen: the sidebar, the footer, the omnibox, the keymap (`keymapModel.mjs`, `shortcuts.ts`), the menu bar icon's model (`trayModel.mjs`), the OS notifications (`notificationsModel.mjs`), where a person was.
- `desktop/src/ui/` — the kit: every primitive a view may use, `icons.ts`, one wrapper per library.
- `desktop/src/theme/` — `tokens.css` (the role contract) and the theme families under `desktop/src/theme/themes/`.
- `desktop/src/scenarios/` — a person's journeys as tests, one `.test.mjs` each, no DOM.
- `desktop/src/api.ts` · `desktop/src/bus.ts` · `desktop/src/types.gen.ts` — the wire; the types are generated by `just gen-types` and never edited.
- `desktop/src/i18n/` — every word the window says ([Translation](translation.md)).
- `desktop/src-tauri/src/` — the shell: `main.rs` (the Tauri commands), `sidecar.rs`, `terminal.rs`, `navigation.rs`, `window_state.rs`, and `desktop/src-tauri/src/tray/` (the menu bar icon, each OS behind `platform.rs`).

## Rules a change must keep

- A view imports from the kit and nothing else; each library is wrapped once (`desktop/src/ui/imports.test.mjs`).
- Nothing in the app names a colour: every theme answers every role in a light and a dark block, and every pairing clears its contrast floor (`desktop/src/theme/roles.test.mjs`, `desktop/src/theme/themes.test.mjs`).
- A fact lives in a `.mjs` model beside its component, with a `.d.mts` and a `.test.mjs`; components are not tested and there is no jsdom (`desktop/src/noHappyDom.test.mjs`); a model that restates what the Rust owns reads the Rust source in its test ([Add a desktop model](../recipes.md#7-add-a-desktop-model)).
- One door each: a remembered choice through `desktop/src/shell/storedPrefModel.mjs`, a screen's state through `useViewState`, a diagnostic through `desktop/src/log.ts` — never `console`; every export is used (`desktop/src/logDoor.test.mjs`, `desktop/src/deadExports.test.mjs`, `desktop/src/localStorageKeys.test.mjs`).
- The webview names a scope and an id, never a path or a program; a word from the shell to the webview is one constant on each side ([Add a Tauri command](../recipes.md#13-add-a-tauri-command)).
- A terminal is never rendered inside the routed screen: unmounting ends the PTY ([crates/desktop § What the desktop refuses to do](../../architecture/crates/desktop.md#what-the-desktop-refuses-to-do)).
- Every chord is a `COMMANDS` entry; a conflict is refused, not stored; `docs/reference/keymap.md` is generated (`desktop/src/shell/keymapModel.test.mjs`, `desktop/src/shell/keymapDocs.test.mjs`).
- The menu bar icon's number is the Inbox's rows that need the person, never the unread; a notice reaches the OS only under its category's switch (`desktop/src/shell/trayModel.test.mjs`, `desktop/src/shell/notificationsModel.test.mjs`).
- `npm run build`, not `tsc` alone: `tsc` does not catch module resolution ([desktop/README.md](../../../desktop/README.md)).

## Testing a change

- `scripts/test desktop <dir>` for the folder you changed — `scripts/test desktop shell`, `scripts/test desktop views/_settings` — or one file from `desktop/`: `node --test --import ./src/i18n/preload.mjs src/shell/keymapModel.test.mjs`.
- `scripts/test desktop scenarios` — every journey; `scripts/test tauri` — the shell's crate (the PTY registry, the sidecar's search, the window's place, the menu bar icon, the navigation policy).
- From `desktop/`: `npm run build` (types and module resolution) and `npm run lint`.
- The end of the pass: `npm run test:coverage` in `desktop/` (`just desktop-coverage`, in `just verify`), which fails under 80 % of lines across the models.
- A journey through the binary has no window; `crates/bisa-cli/tests/it/e2e/the_nodes_wire.rs` holds the wire the window reads, and `desktop/src/scenarios/wire.test.mjs` holds how the window lives it.

## Compatibility

- The desktop's code, the window's place and what each screen remembers are not promised ([Not promised in 0.x](../../reference/compatibility.md#not-promised-in-0x)); a remembered choice of another version is never reinterpreted.
- What is promised here: every keymap command id — `keymap.overrides` is keyed by them ([The keymap](../../reference/compatibility.md#the-keymap)) — and the settings keys the panels write ([Settings keys](../../reference/compatibility.md#settings-keys)). A new command or key is additive; renaming an id waits for 1.0.0.
- The desktop is a client of [the HTTP API](../../reference/compatibility.md#the-http-api-and-its-events) like any other: it ignores fields and codes it does not know and switches on an error's `code`.
- Declare your change's compatibility in the pull request ([Keeping compatibility](../compatibility.md)).

## Review focus

- A fact in a component instead of a model, a model without its test, a library imported outside the kit, a colour or a storage key spelt by hand ([Code review](../review/code.md)).
- A poller that runs while the window is hidden, a store that re-renders when nothing moved ([Performance review](../review/performance.md)).
- A path or a program crossing from the webview to the shell; a secret in a field that is not the kit's one secret field ([Security review](../review/security.md)).
- Every word through the catalog, a Settings path as the rail shows it ([Docs and language](../review/docs-and-language.md)); a new package's licence ([Licences review](../review/licences.md)).
